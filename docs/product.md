# 产品说明

简体中文 · [English](product_EN.md) · [README](../README.md)

## 定位与目标用户

`miocli` 是面向单个已运行 Mihomo 实例的键盘优先终端操作台，服务已经部署内核、希望在本地终端或 SSH 会话中完成日常代理操作的进阶用户。

参考 [k9s](https://github.com/derailed/k9s) 的资源操作台定位，核心价值是“浏览资源 → 执行操作 → 确认结果”，而不是管理被连接系统的安装和生命周期。miocli 是控制 API 的客户端，但不是只能看状态的查看器，也不是一体化代理运行器。

### 为什么不包含内核

目标用户已有内核，重复部署不是主要需求。将内核安装、启动、升级和完整配置管理纳入产品，会增加进程、版本和配置来源的责任，也会与已有桌面客户端争夺运行环境。产品优先投入高频操作的效率与可靠性，而非扩大开箱即用的范围。

代价是新用户必须自行准备可访问的 Mihomo controller；miocli 不负责使代理服务从零运行起来。

## 核心任务与功能

1. **找组与切节点**：搜索代理组，浏览成员和嵌套组，切换 `Selector` 成员，并通过 API 读回确认。
2. **测试延迟**：测试单节点、筛选结果或当前组的直接成员；按协议或来源筛选节点，按 API 顺序、名称或延迟排序。
3. **更新 provider**：查看已有内核的 proxy-providers，手动更新并读回状态，随后刷新代理组与节点数据。
4. **辅助控制与观察**：切换 Rule、Global、Direct 模式；查看活跃路由摘要、实例和诊断状态。

界面包含 Groups、Nodes、Providers、Status 四个英文导航项，数字键依次为 `1`、`2`、`3`、`4`，默认进入 Groups。

- Groups 以代理组和成员为主要操作对象。
- Nodes 是独立的全局节点列表；浏览或选中节点不会自动改变某个组的选择，切换需在 Groups 中选择 `Selector`。
- Providers 是已有 controller 提供的 API 资源，不是完整 YAML 配置档案；来源更新由 Mihomo 执行。
- Status 展示连接与实例状态，并区分活跃连接链路和当前浏览光标。

## 操作与安全边界

- 仅连接一个 controller，不取得进程所有权；退出不停止或重启外部实例。
- 不安装、下载、启动、停止或升级 Mihomo，不接管系统代理、TUN、系统服务或权限提升。
- setup 只保存操作台的连接设置；可以手动输入地址和密钥，或指定 Mihomo YAML 只读提取 controller/secret，不扫描客户端目录、不猜测密钥、不写源 YAML。
- `doctor` 只读检查配置与 API；`dev` 只使用仓库本地连接配置。
- 只有 `Selector` 组允许手动切换成员；延迟测试、模式变更和 provider 更新显示错误或未确认状态。
- 写请求超时不自动重放；无法读回状态时，保留最后成功读取的数据并显示错误，不报告未确认操作成功。
- 不支持完整配置订阅、配置合并或热加载、规则覆写、分组结构编辑、多实例、实时流量图、日志查看或关闭单个连接。

## 安装

CLI 安装器从 GitHub 获取 miocli 发布包并校验 SHA-256，失败时保留已有程序；安装 CLI 不等于安装内核。详见 [README](../README.md)。
